# Linux Markdown 作业

## 写作

- 先读题目、评分要求和用户提供的材料，逐项覆盖要求；不把过往作业的具体章节当作固定模板。
- 用中文写清楚的一级标题和分层小节；有身份信息要求时写姓名、学号，具体值以本次材料为准。
- 概念先用自己的话解释，再给与题目直接相关的例子。命令、路径和语法用行内代码，较长示例用标注语言的代码块；列表和表格只在有助于阅读时使用。
- 需要学习反思时，区分已掌握、尚不熟悉和实际练习过的内容。只写真实学习与操作，不把计划或示例说成已经完成。
- 完成后检查标题层级、代码围栏、链接、图片语法和文件名，并通读是否有重复或与题目无关的内容。

## 命令实践类作业

- 按题目要求的类别组织命令。每条命令简述用途，并给出与本次实验环境相符的可执行示例；涉及前置文件、账户、服务或软件时先交代准备条件。
- 区分“命令示例”和“已实际运行的结果”。有截图或终端记录时，说明它证明了哪一步；没有证据时不虚构成功输出。截图使用作业目录内可访问的相对路径和有意义的说明，交付前检查图片确实存在。
- 出现错误时依次写现象、相关命令或报错、分析、实际采取的处理办法和处理后的结果；尚未解决的就明确写未解决。
- 删除文件、修改权限或用户、写入磁盘等操作尽量限定在测试环境；示例应标出可能影响的数据或所需权限。
- 总结具体学到了什么，以及问题如何改变对命令使用条件的理解，避免逐条复述命令清单。
