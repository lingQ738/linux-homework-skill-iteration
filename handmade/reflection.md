# 第一次作业的写作反思

第一次作业围绕 Markdown 基础语法、工具、高级用法和结构化提示词展开。现存作业表明，我此前已经接触标题、列表、粗体、链接、行内代码、代码块和简单表格；相较之下，LaTeX 公式、Mermaid、Marp、Pandoc 以及结构化 Prompt 是当时需要进一步学习的内容。写这类作业的难点不只是查到语法，还包括确认示例在实际编辑器中能正确显示，并把“了解用法”与“亲自实践过”分开写。

如果重做第一次作业，我会先依据题目列出必须回答的问题，再为每个问题准备一个可运行或可预览的例子。公式和流程图应在使用的 Markdown 工具中预览；代码围栏应检查语言标记与闭合；链接和图片应检查目标是否可访问。遇到不会的语法，我希望得到的是最小示例、解释和检查方法，而不是直接得到一整篇无法核实的作业。对于 CO-STAR 等提示词框架，我需要先弄清各字段如何帮助表达背景、任务、限制和输出格式，再按自己的学习需要改写。

这些观察对应了 v1 Skill 中的几条初始规则：先对照题目组织层级，用清楚的代码块呈现命令或语法，按实际掌握程度写反思，完成后检查格式与无关内容。后续版本把检查从排版扩展到实验环境、截图、源码和运行证据；这说明一份 Linux 作业的质量不只取决于文字是否整齐，还取决于结论能否被当次材料支持。
